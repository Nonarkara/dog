## Tamagotchi: keep the loop small

Bandai's [original manual](https://tamagotchi-official.com/manual/toy/original/)
uses a small vocabulary of care actions, visible needs, a call for attention,
rest, cleanup and play. The design inference here is a short loop:
**notice the dog → choose care → see a bodily response → remember what helped.**
The manual does not prove that any particular mechanism causes addiction.

This game already has the useful pieces: one next-need sentence, persistent
individual personality, active care days, a small pantry, park outings and
short training sessions. Preserve these rather than adding more dashboards.
There is no new streak punishment, scarcity timer or randomized purchase.
The illustrative three-step lesson stays beside its one current action.
The desktop training panel now earns only the space that lesson needs.

The conditioning equations are game adaptations, not validated predictions
of an individual real dog's mind. Compound blocking is a tested helper; the
current spoken-word interaction is a single cue, not a compound-cue trainer.
For real capture training, first mark/reward an offered behavior; add its cue
when it becomes predictable. See [AKC capturing guidance](https://www.akc.org/expert-advice/training/put-your-dogs-cute-behaviors-on-cue/).
Regular meals remain independent of success at tricks. The game never asks
players to starve a dog to improve training.

## Promises checked

| Promise | Honest boundary |
|---|---|
| Your dog returns in this browser | Requires browser storage to remain available; clearing site data removes it. Export remains available. |
| Your dog follows your account | Only after successful account uploads; different companions/accounts require a choice. Revision conflict pauses uploads. |
| Closing saves everything | Not guaranteed by browsers. Periodic foreground upload and local save remain; the save-status control explains this. |
| Email/password recovery | Clerk integration is prepared but disabled until credentials and actual delivery/recovery checks are completed. Google/LINE retained. |
| A living-looking dog | Authored 2D poses plus joint interpolation and shader micro-motion. Still 2D; no claim of a full 3D skeleton. |
| Gentle persistent care | Growth/personality persist. Offline decay and the existing three-day runaway/reunion mechanic remain; there is no death mechanic. |
| Health notebook | Starter medical entries remain visibly unverified; care is game logic, not veterinary diagnosis. |
| Free hosting capacity | No fixed player count promised. D1 row writes, Workers requests and park resources need actual usage measurement. |

## Palette and affordances

Consulted Palette's local `PALETTE-FIELD-GUIDE.md` and the existing verified
Wada plate mapping in `design/personality-palettes.md`. Preserve NonArchitecture
handwriting, symbolic care controls, accessible names and the control legend.
Rooms gain personality through large color fields, rather than extra decorative
chips. Mali/Paolo/Marigold inks were slightly deepened after contrast failures.
The dog stays dominant; text and action bars remain compact.

## Security and verification limits

The security integration suite exercises forged/expired/wrong-origin managed
sessions, CSRF, account isolation, logout/revocation, deletion retry, export,
malformed saves, race ordering and byte bounds. No credentials are added.
Dependency audit is clean for production packages. This is a targeted review;
provider compromise, browser malware and exhaustive abuse/load tests are outside
this release. Real Clerk forms, email delivery and recovery are still unverified.
No phone battery or low-end-device hardware benchmark was conducted. The motion
repair adds no new textures or network assets and preserves hidden-tab suspension.

Browser checks cover 320/390/1024/1440 layouts, real training interactions,
park locomotion, retained canvases, save conflict UI and visible save explanations.
See the scripts added/updated with this release for repeatable checks. Existing
one-screen and visual scripts were also rerun; test-only waits/disclosure steps
were updated to match the current rendered UI instead of racing a paint.
